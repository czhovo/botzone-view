# Ataxx：五位参与者的 ponder 讨论

已在原生 CLI 的原对话中分别与 Astra、Sol、DeepSeek Flash、Qwen 和 GLM 讨论 ponder。**五位封存提交均未使用 ponder，也没有找到它们实际进行 ponder 开关测试的记录。Flash、Qwen 当时明确考虑过；GLM 本次表示当时没有考虑；Astra、Sol 没有可确认的考虑或评估记录。**

讨论发生在全部相关提交封存之后，禁止工具执行、修改程序和追加测试。完成后核对五份封存源码及个人工作区源码，均未改变。Sonnet 按用户要求跳过访谈，余额中断后没有再向其发起模型请求。讨论用量不计入开发 token 或开发价格；既有开发价格文件保持不变。

ponder 是本方回复后、等待对手期间继续搜索，可能预热置换表（TT）或提前探索对手应手。进程常驻、缓存跨行动保留、多线程用于当前回合截止保护、主办方并行运行多局，都不自动等于 ponder。

## 具体讨论得到的澄清

**协议允许与实现能力是两回事。** 持久进程不因只在己方行动时收到请求，就被禁止在等待期间计算。当前阻塞式读取需要改架构才能利用间隙；并非原则上必须双线程。Qwen 本次提出单线程分片搜索与轮询方向，但没有实现或验证，本记录不承诺某个具体 API 或停止延迟。

**跨行动缓存不等于 ponder。** 即使程序等待时完全不计算，也可保留上一轮 TT、排序启发和静态评价缓存。Sol 的 worker 在当前回合搜索、发布结果后停止收尾，不是对手回合的持续预测搜索。

**预测条目的来源不决定有效性。** Flash 第一轮把“没有实际/预测标记”列为不能安全复用的原因。补问后它撤回：如果局面、行动方、历史约束、剩余步数及搜索语义等条件匹配，预测分支中算出的条目也可以有效。来源标记不是普遍正确性要求。其既有哈希、历史及跨轮键设计的具体限制，是另外的问题；本次未增加新的源码探针来量化它们的影响。

**停止检查点不是时间保证。** GLM 起初认为每隔 1024 节点检查即可毫秒级停止，补问后撤回。节点间隔受节点成本和调度影响；输入到达、取消、汇合及新局面重建都未测。封存版的单线程守时数据不能证明新增 ponder 后的取消路径守时。

**墙钟和 CPU 工作量不能混加。** GLM 起初以双向 ponder 推断长局逼近 700 秒限制，补问后撤回。ponder 与对手回合重叠，不能将两份时间直接相加；400 步是双方合计。额外计算可能通过负载影响实际回复延迟，但幅度未经测量；若先超过单步 1.5 秒截止，则直接判负。停止和交接也属于从收到请求到完整回复的一秒名义预算。

**缓存更深不等于上下文正确。** GLM 的“只写较深条目”及“独立表合并”被降级为未验证设想。历史禁着和剩余步数等语义若不匹配，更深条目不会自动变得可用，合并也仍需核对条件。

**一次启动离群不能确定原因。** Flash 以一次较慢启动呼应调度风险，补问后撤回。启动、单步服务时间、回复后空闲间隙和取消延迟是不同量；没有分解测量，不能用启动离群证明调度抖动，更不能作为 ponder 的停止延迟证据。

## 如何理解这次答复

Flash 对收益的早期判断较轻，没有实验；Qwen 对同步风险作了较具体的分析，但对收益只有估计，并遗漏单线程轮询这个选择。Qwen 本次进一步认为当时调参也受到已知根选择问题干扰，这是它的事后反思；“所有对照信息量接近零”等扩大结论不作为主办方新确认的事实。

Astra、Sol 没有为了回答问题编造明确的当时取舍，而把可能的工程权衡标为事后解释。GLM 也明确区分相邻的 TT 复用设计与并未考虑过的 ponder。这些答复说明决策记录和解释范围，不构成棋力排名。

当前证据不能认定其余五位“测过后发现 ponder 没收益”。准确说法是它们都没有实施和测量；只有 Flash、Qwen 有明确的当时考虑记录。Sonnet 在开发中确实实现并测试过 ponder，但其封存配置按用户要求保持关闭；详细选择过程在 Sonnet 报告中单独记录。没有因这次讨论进行新的对战或改变任何程序。
